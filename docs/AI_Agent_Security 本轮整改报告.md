## 2. 问题、根因与修复

| 优先级 | 问题与根因 | 本轮处理 |
|---|---|---|
| P0 | 概念分类器看到“提示词注入”“是什么”，抢先处理索要论文的请求；模型分类也可能重复这个错误 | 文献、标准、政策及来源请求优先进入证据检索；明确 CVE 仍走漏洞查询；保留纯概念与产品定义模式 |
| P1 | 资产缺字段触发 KeyError→500；str/int 与 `or` 默认值把空值、容器、小数或 0 转成有效资产 | 必填字段必须为非空字符串；重要度为严格整数 1–5；拒绝布尔、小数、显式 null；暴露面为枚举，owner 为字符串；非法请求返回 400 且不写库 |
| P1 | live 请求先响应、后台才抢锁，第二次请求可能假 queued | 所有 live 入口共享原子锁准入；创建任务后再启动线程；忙时 409，不增加任务；启动线程失败记录 failed 并释放锁 |
| P1 | 前端只刷新两次，长任务结束无人跟踪 | 返回 run_id，新增按编号查询接口；每 2.5 秒查询本次任务，最长 120 秒，结束刷新；超时或查询失败诚实提示后台可能仍在运行 |
| P1 | 原有测试未穿过 HTTP 解析、路由及响应边界 | 增加真实 localhost 随机端口、临时数据库、禁用云端与模拟采集来源的集成测试；关闭服务器并检查线程退出 |
| P2 | CI 评测结果只写临时文件，失败难定位 | tee 输出 JSON、pipefail 保留失败退出码、上传评测 artifact；显式安装 Node 并执行 JS 语法校验 |
| P2 | README 对 OSV 覆盖能力表述过强 | 改为部分补充，不承诺完全替代 GitHub Advisory |

## 5. 选择性采纳与未执行项

- 不采纳“仅先检查 is_running 再启动线程”：检查与启动之间存在竞争窗口。以同一把锁原子占用执行权。
- 不按“只要提产品就优先证据”机械分流：产品定义仍可概念解释，论文及当前漏洞事实才走证据路径。
- 使用 `/api/runs/{id}` 精确跟踪，不从最近任务列表猜测当前任务，避免并发或历史记录混淆。
- 暂不增加 Playwright、浏览器二进制和独立 E2E workflow。当前新增的是真实 HTTP 集成及 Node 行为测试，不能称为完整浏览器 E2E，视觉交互仍需人工验收。
- 暂不增加 Docker 构建步骤；本轮未实测 Docker 构建和运行，不能承诺容器可用。
- 保留 GITHUB_TOKEN 的环境变量读取方式；不硬编码凭据，不因 403 伪造来源成功，也未凭猜测替换 CISA 来源。本轮不验证真实外网来源可达性。
- 未重写 GLM prompt：本次已证实的问题发生在路由层。未调用付费模型，不能声称本轮提高了真实 GLM 回答准确率。
- 修改尚未提交或推送，远端 CI 未针对本轮运行；不能宣称 GitHub Actions 已绿。

## 6. 剩余边界与现场使用建议

| 模式 | 判断 |
|---|---|
| 离线 Demo | 可以作为固定演示主路径，已有可复现回归；仍应走一遍真实浏览器演示流程 |
| 在线采集 | 状态链路与失败隔离已验证；现场网络、限流和来源稳定性未验证，应作为辅助展示并提前试采 |
| GLM | 保留配置和既有能力；本轮只做隔离测试，赛前需验证实际账号、额度、延迟与代表性问题 |
| Docker | 本轮未验证，现场主路径不建议未经演练直接切换到容器 |

9/9 是 9 条开发样例的规则验收，不是独立问答准确率，也不能证明满足赛题 95% 指标或保证高级奖项。仍缺独立留出集、语义人工盲评、真实多跳问题和高并发测试。路由仍含词法启发式，复杂混合意图可能需要继续补充案例。

互斥锁是单 Pipeline、单进程语义；多进程部署需单独设计协调机制。前端轮询超时不会取消后台任务，也不能解决进程崩溃后的持久化执行恢复。这些超出本次最小修复范围。
