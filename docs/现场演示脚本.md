# 知盾 AI 安全情报系统：5 分钟现场演示脚本

> 适用版本：当前离线原型。目标是展示**已运行的功能和可核验的证据**，不把离线开发样例说成实时监测成绩。配套说明见[README](../README.md)、[赛题剖析与设计原则](赛题剖析与设计原则.md)和[10 个开源项目调研](开源项目调研.md)。

## 开始计时前：预检

1. 在项目根目录运行 `python3 scripts/evaluate.py` 并记录真实结果。它对 7 条离线摘要、3 个虚构资产、9 道固定题做**开发规则自测**；即使规则 9/9 通过，也不是赛题官方问答准确率。无 Docker 环境时用 Python 原生入口。
2. 在**空数据库路径**启动纯离线演示：`env -u LLM_BASE_URL -u LLM_MODEL -u LLM_API_KEY ZHIPU_API_KEY='' python3 -m app.server --no-scheduler --db /tmp/zhidun-stage-new.sqlite3`。命令中的空值会临时压过项目根 `.env.local` 的智谱密钥，不改动密钥文件。若数据库路径已排练过，换一个尚不存在的文件名。打开 <http://127.0.0.1:8765>，检查“本地服务已连接”。`--no-scheduler` 关闭自动在线采集；空密钥保证问答不请求 GLM。
3. 预先准备两个网页标签：[GitHub 的 Ollama 公告](https://github.com/advisories/GHSA-8hqg-whrw-pv92)和 [Wiz Research 独立分析](https://www.wiz.io/blog/probllama-ollama-vulnerability-cve-2024-37032)，必要时现场点开核验。若会场断网，展示系统保存的标题、URL、发布时间，并明确外链暂时无法打开。
4. 屏幕只展示项目和公开情报；虚构资产不带真实 IP/域名，不展示 `.env.local` 或密钥。按赛事决赛规定，答辩 PPT 不放学校、队伍单位或人名。〔赛题 PDF，第 3 页〕

## 0:00–0:35　定位与数据口径

**操作**：停留“总览仪表盘”，指出漏洞实体、知识文档、证据关系三张卡，鼠标指向“演示采集”和“在线采集”两个按钮。

**建议讲述**：

> “知盾围绕赛题的监测、富化、问答三段闭环开发。此刻屏幕显示的是仓库内的公开来源人工摘要，不是刚从互联网抓到的实时情报。空库启动会自动导入 7 条文档，其中有 3 个真实漏洞 CVE；在线配置与持续覆盖、时效需要另行取证，不能从这组离线样例推断。”

**证据**：总览数字与“演示”批次；不要把“已配置来源”或演示来源健康数说成在线成功数。

## 0:35–1:15　监测、归一和重放去重

**操作**：点击“演示采集”，看提示中的 `fetched / inserted / skipped`；切到“运行与轨迹”，展示新批次和“监测代理 → 分诊代理 → 富化代理 → 索引代理”事件。首次空库自动导入后，手动再点击应出现 7 条重放跳过，文档总数仍为 7。

**建议讲述**：

> “采集器先验证 AI 相关性并归一 CVE/GHSA，再以来源 ID 和原始记录 ID 做幂等写入。这里的 7/7 跳过，只证明本地相同快照重放去重，不代表对未知在线来源的去重准确率。”

**若提示数值不同**：先看是否使用旧数据库或已有联网记录；照实解释当前库的 `inserted/skipped`。无需重置、删除或改造数据来凑演示数字。

## 1:15–2:05　漏洞证据、两个来源与虚构资产

**操作**：打开“漏洞情报”→ `CVE-2024-37032` 的“证据详情”；依次指向：两个来源文档、版本/修复事实、资产匹配。点开其中一条“核验原文”链接（网络允许时）。然后切到“授权资产”，指出名称前缀“演示-虚构-”。

**建议讲述**：

> “同一 CVE 关联 GitHub 公告和 Wiz 研究分析，但两者措辞不同。公告确认 Ollama 0.1.34 前受影响、0.1.34 修复；研究文章讨论特定暴露和部署条件下的进一步影响。我们把每条事实留在对应来源下，不把研究推断强行写成官方公告结论。这个 Ollama 节点是虚构资产，仅以登记版本 0.1.33 与公告区间匹配。系统没有扫描真实互联网资产。公告没有可核验 CVSS 数值，优先级显示待评估。”

**核验点**：[GitHub Advisory](https://github.com/advisories/GHSA-8hqg-whrw-pv92)、[Wiz Research](https://www.wiz.io/blog/probllama-ollama-vulnerability-cve-2024-37032)、`data/demo_records.json`、`data/demo_assets.json`。两份来源归并不等于两条独立漏洞。

## 2:05–3:05　同 CVE 双源问答与多轮上下文

**操作**：进入“Agent 问答”，逐字输入：

1. `CVE-2024-37032 的修复版本和本地受影响资产是什么？`
2. 不点击“新建会话”，继续输入：`接着说，它的风险等级与修复版本？`
3. 新建会话后输入：`ollama 有哪些漏洞和相关研究分析？`

**建议讲述**：

> “第一问沿 CVE → 产品 → 本地登记资产的路径，给出修复版本、虚构资产匹配，并列出两份来源链接。第二问保留会话中的 CVE 上下文，继续引用公告与研究文章；风险等级 Moderate 来自 GitHub 公告，不能概括 Wiz 对特定场景的风险分析。第三问从 ollama 找到对应 CVE，再显示与这个 CVE 同组的 Wiz 分析文章；`same_cve_group` 表示按同一漏洞标识归并，不是模型独立发现的新因果关系。答案下方的引用和路径可以逐项复核。”

**证据**：前两问的 `[1]`、`[2]` 引用，`affects_product` 和 `local_asset_version_match` 路径；第三问的 `same_cve_group` 边。此处是同 CVE 来源归并与有限会话状态，不宣称通用跨文档多跳推理已达到官方优秀档。

## 3:05–3:40　论文、标准、政策知识底座

**操作**：打开“知识底座”，按类别分别点“研究论文”“技术标准”“政策法规”；选看 [AgentDojo 论文](https://arxiv.org/abs/2406.13352)、[ISO/IEC 42001 官方介绍](https://www.iso.org/standard/42001)、[网信办《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。

**建议讲述**：

> “漏洞之外，系统把学术论文、标准、政策法规作为不同类型的知识文档单独索引。ISO 条目只保存公开介绍摘要，并未复制付费标准全文。文档可回到原始页面；知识底座与漏洞监测来源类别分开统计。”

## 3:40–4:10　证据不足时的拒答

**操作**：回到“Agent 问答”，新建会话，输入 `CVE-2099-99999 的修复版本是什么？`。

**建议讲述**：

> “数据库没有这个 CVE，系统明确拒答且不生成虚构修复版本。离线样例尚无 PoC 链接；在线发现 PoC 相关链接也只作为待核验元数据保存，本项目不会执行验证代码。”

**证据**：回答“未在本地知识库找到……”，无引用。不要把拒答率等同于完整问答准确率。

## 4:10–4:40　可重复测试与工程边界

**操作**：在终端展示预先运行或现场运行的 `python3 scripts/evaluate.py`，快速指向样本量、原样重放跳过比例、固定规则通过率、必需来源引用存在率和进程内 p50/p95；再回到“运行与轨迹”展示事件日志。无需点击“在线采集”，以免会场网络与外部服务影响 5 分钟时长。

**建议讲述**：

> “这是临时 SQLite 上的离线开发样例自测：7 条文档、9 道固定题（基础 5、同 CVE 双源/关联 3、拒答 1）。评测脚本、预设规则和数据 SHA-256 都在仓库，可重复运行。即使全部规则通过，它也不证明真实发布到采集 ≤6 小时、完整 HTTP 答案 ≤5 秒，或大样本富化和问答 ≥95%。”

## 4:40–5:00　结尾与限制

**建议讲述**：

> “目前已跑通证据可追溯的离线闭环、跨源同 CVE 归一、虚构资产版本推断与有限会话追问。12 个在线源条目中有 9 个监测候选源、3 个知识底座源；一轮开发联网观察不能证明持续覆盖。真实监测类别与时效、富化精确率与召回率、问答语义准确率均需独立真值和原始运行记录验证。”

**停在画面**：总览或漏洞详情，让评委看见原文出处。答疑时用[赛题剖析与设计原则](赛题剖析与设计原则.md)中的初赛/决赛评分矩阵，清楚区分“已实现”“自测通过”“未验证”。
