# 系统审计与整改记录

审计日期：2026-09-29。对象：赛题 9「智能体驱动的 AI 安全知识情报系统设计与实现」当前代码、离线数据、Web 界面、评测脚本及提交材料。结论基于仓库检查、单元测试、开发样例回放和一条 GLM-5.3 真实 HTTP 问答；它不是第三方测评报告。

## 总体判断

系统已经是**可运行的竞赛原型**：离线摘要进入 SQLite，跨来源归并同一 CVE，抽取可追溯声明，匹配本地登记资产版本，再以带引用的问答呈现。其主要优势是证据和轨迹清楚。现在不能称作已达到「高级奖项」的实证作品，因为赛题优秀档的核心量化指标尚无独立评测：7 类持续实时监测、≤6 小时延迟、至少 5 个自动富化维度及 ≥95% 精确率/召回率、复杂问答 ≥95% 准确率。这些是后续攻关目标，不是现有成绩。

## 尚未解决的竞赛关键缺口

1. **监测证据不足。** `config/sources.json` 有 12 条在线配置，其中 9 条是监测候选。此前一次 10/12 成功、134 篇入库的开发观察没有附原始批次日志；新增的[全源归档](evidence/2026-09-29-全源在线采集验收.md)证明一次短时运行中 10 条任务成功、442 篇入库，但有成功源无匹配内容，且 3 条为知识底座、2 条返回 403。应连续保存至少数日的每源任务原始结果、发布时间、首次采集时间、失败原因和去重明细。按赛题口径人工判定真正独立的来源类别；不能把多个公告镜像算作不同类别。
2. **富化指标未测。** 当前 claims 主要从结构化源字段和人工摘要抽取，证据片段通常是摘要而非每个字段的原文定位。需要冻结真实样本、逐字段人工标注和双人复核，分别计算精确率、召回率、错误关联率。PoC URL 目前只作为待核验线索；不执行 PoC 是合理边界，但要避免把链接发现写成可利用性验证。
3. **问答泛化未测。** 9 道固定题与离线 fixture 同源，只能防回归。需要独立留出题集，覆盖新漏洞、跨独立文档推理、来源冲突、无证据拒答、错别名和时效冲突；人工逐条判定事实、证据是否支持断言及关系路径是否真实。GLM 成功调用本身不能证明准确率提升。
4. **性能和运行安全未测。** 目前的离线耗时是进程内规则问答；一条 GLM HTTP 问答约 2.7 秒不代表 p95 或高并发表现。服务默认本机绑定，没有登录授权；现场局域网/公网部署前需要鉴权、限流、密钥管理和持续运行压测。Docker 配置存在，但此环境未实测构建。
5. **提交材料待外部证据补齐。** 报告和 PPT 已有源文件；演示视频未录制。结论中所有量化语句都应附原始日志、题集版本和复现实验命令。决赛匿名要求需人工复核页脚、视频画面与文件元数据。

## Agent 盘点回答专项修复（2026-09-29）

用户截图暴露的问题：高危盘点忽略“推理框架”主题，最新八条挤掉较旧相关产品；模型额外推断资产意图，导致每条重复无资产提示。旧提示词只允许规划/段落筛选，不能据此称作自主深度分析。

本次改为按产品主题筛选、分页读取、按漏洞编号去重，代表条目优先覆盖不同产品；模型接收公开候选摘要并只返回文档编号参与排序。回答显示总数、代表条目、原文摘要、高危口径、最新来源发布日期及本地覆盖边界。修复版本使用所引用文档字段，避免串用另一产品的补丁。资产信息仅在明确提问时聚合，且不作为模型排序输入。模型阶段标记改为请求局部状态，避免并发请求互相污染。长回答显示开头而非自动跳至引用末尾。

当前数据库的截图原问题在本地规则复测中得到 14 个相关高危漏洞，覆盖 vLLM、LMDeploy、llama-cpp-python，展示 8 个引用。新增测试覆盖无关高分干扰、超过 200 条公告积压、未询问资产却被模型加意图、排序失败回退、产品高危过滤及引用覆盖。该结果是开发回归证据，不是独立准确率评测。

仍有局限：主题分类使用显式产品词典；模型目前参与规划和排序，不自由生成分析结论。原文摘要保留来源语言，复杂机制解释与跨文档综合仍需后续独立评测后增强。
